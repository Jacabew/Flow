Facts only. What exists now that didn't before.

- 2026-10-23: Repo created. Engine core (steps, retries, run log, approvals, pause/resume, alerts), scheduler (Brisbane time), HTTP API with key auth + webhook triggers, heartbeat flow, 13 passing tests, CI on Node 22/24, HUB auto-deploy script with test gate + health check + auto-rollback, one-time HUB installer. Not yet installed on the HUB.
- 2026-10-23 (night build): Watchdog flow (every 5 min; alerts once per outage if no successful heartbeat in 15 min; 15-min start-up grace; logs recovery). Daily summary flow (00:10 Brisbane; writes yesterday's runs/failures/alerts per flow to FLOW_STATUS_DIR\daily.json, atomic write). Flows can now read run history via ctx.store/ctx.now/ctx.engineStartedAt. Installer sets FLOW_STATUS_DIR=OneDrive\FLOW\status. 22 passing tests.
- 2026-10-24 (night build): Retention flow (00:20 Brisbane) moves finished runs older than 30 days to `data\archive\runs-YYYY-MM.json` (Brisbane month; archive written before removal; runs waiting on approval never archived). Start-up recovery marks runs left "running" by a restart/crash as failed and alerts once each. Store gained `remove()`. Run safety cap raised 5,000 → 20,000. 29 passing tests.
- 2026-10-25 (night build): Every step attempt is now time-limited (default 5 min; http 30s + 1s; wait = its length + 5s; override with `timeoutMs`). Timeouts fail the step, count toward retries and alert like any failure; steps get `ctx.signal`, which aborts on timeout (http and wait honour it). Schedules accept `weekly: 'Mon,Wed 07:30'` and day names in `days`; every schedule is validated when its flow registers, so a typo throws instead of never firing. 36 passing tests.
- 2026-10-26 (night build): Phone approval inbox at `GET /inbox`: one static page (no data in it, no-store, CSP, no framing) that asks for the API key once, keeps it in that phone's localStorage, lists pending approvals (title, flow, Brisbane time, detail) and approves/rejects via the existing API; reloads when reopened; bad key returns to login. Approve/reject on an unknown id now returns 404 (was 500). Checked in headless Chromium at phone width. Not reachable from a phone yet: server is still bound to 127.0.0.1 (next task decides the route). 39 passing tests.
- 2026-10-27 (night build): `/api/summary` frozen as schema 1 (adds `schema`, `generatedAt`, `sinceHours`, `status` green/amber/red, ready-to-show `headline`, `failedFlows`, `lastFailureAt`; existing fields unchanged) and documented in new `docs/API.md` with every endpoint. API key check is now constant-time, and 10 wrong keys from one client in 15 min returns 429 for that client (real IP taken from the last X-Forwarded-For entry when behind Caddy). `docs/DSOS_REQUESTS.md` has two ready-to-apply requests: Caddy route `flow.darkspace.au` exposing only the inbox + approval endpoints, and the Mission Control "Automations" tile. 43 passing tests.
- 2026-10-28 (night build): Store is now an append-only log per collection (`data\<name>.jsonl`, one line per insert/update/remove) instead of one JSON file rewritten on every change; write cost no longer grows with the number of runs kept. Log auto-compacts (temp file + rename) when stale lines outnumber live rows by 2,000+. A torn last line after a crash is skipped (copy kept as `.corrupt-*`). Existing `<name>.json` files are imported once and renamed `.json.migrated`. Same store interface, no engine changes. 50 passing tests.
- 2026-10-29 (night build): DSOS connector: new `dsos` step type (`path: '/api/v1/...'`, `query`, `body`, Bearer token). Token from `FLOW_DSOS_TOKEN` or `C:\Flow\secrets\dsos-token.txt` (read each call, no restart needed); URL defaults to `http://127.0.0.1:3000`. Writes (POST/PUT/PATCH/DELETE) are shadow by default: not sent, recorded in a `shadow` log at `GET /api/shadow`; real only with `live: true` on the step AND `FLOW_DSOS_WRITES=live` on the HUB (neither set anywhere). Paths locked to `/api/v1/` plain characters so the token can't go elsewhere; token scrubbed from errors. Reads retry twice, writes never retry. `GET /api/connectors` shows configured yes/no. Installer now sets `FLOW_SECRETS_DIR`. No flow uses it yet. 59 passing tests.
